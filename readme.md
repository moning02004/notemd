# note.md

마크다운으로 노트를 작성하고, 검색하고, 워크스페이스 단위로 공유하는 셀프호스팅 노트 애플리케이션입니다.
FastAPI(백엔드) + Next.js(프론트엔드) + PostgreSQL + Meilisearch + Celery로 구성되어 있고, Docker Compose로 전체 스택이 한 번에 뜹니다.

**1인 개발 개인 프로젝트** · 2025년 11월 ~ 2026년 8월 · 커밋 201개

## 무엇을 만들었나

개인 또는 소규모 팀이 직접 띄워 쓰는 노트 서비스입니다. "노트를 쓴다"는 기본 기능 위에,
실제 서비스라면 필요한 주변 요소 — 저장 이력, 휴지통 만료 정책, 전문 검색, 공유 권한, 본문 암호화 — 를
직접 설계하고 붙이는 데 초점을 뒀습니다.

| 항목 | 규모 |
|---|---|
| 백엔드 | Python 약 3,200줄, 도메인 모듈 7개, API 엔드포인트 41개 |
| 프론트엔드 | TypeScript/TSX 약 6,000줄 |
| 테스트 | 백엔드 API 테스트 31개 (in-memory SQLite) |
| DB | Alembic 마이그레이션 16개 |
| 인프라 | Docker Compose 서비스 7개 + GitHub Actions 이미지 배포 |

## 주요 기능

**노트 작성**
- Tiptap 기반 WYSIWYG 에디터 — 표, 체크리스트, 토글(접기/펼치기), 이미지 드래그&드롭 업로드
- 코드블록 14개 언어 하이라이팅과 복사 버튼, `>>` + 공백을 입력하면 토글 블록으로 바뀌는 입력 규칙 등 직접 구현한 확장
- 자동 저장: 바뀐 필드만 골라 PATCH로 보내고, 본문·제목은 타이핑이 멈춘 뒤(500ms), 설정 변경은 즉시 저장
- 템플릿을 만들어 새 노트의 시작점으로 사용

**정리와 검색**
- 태그, 카드/리스트 보기 전환, 정렬, 20개 단위 페이지네이션
- Meilisearch 전문 검색 — 노트를 저장·삭제·복구할 때마다 색인을 동기화하고, 검색은 사용자 단위로 격리
- 휴지통(소프트 삭제)과 복구, 사용자가 고른 보관 기간(15일 / 30일 / 보관 안 함)에 따라 매일 자정 Celery Beat가 만료분을 영구 삭제

**이력 관리**
- 노트 스냅샷 저장·복원·삭제
- 스냅샷 생성 정책을 사용자가 선택: 수동 / 하루 첫 편집 시 / 매 편집 시. 공유 중인 노트는 정책과 무관하게 편집마다 스냅샷을 남겨 누가 언제 고쳤는지 추적

**공유**
- 워크스페이스에 멤버와 노트를 묶어 공유, 멤버는 공유된 노트를 편집 가능
- 공개 링크로 로그인 없이 열람, 필요하면 노트별 비밀번호 설정

**가져오기 / 내보내기**
- PDF(텍스트 추출), 마크다운, 코드 파일 업로드 → 노트로 변환 (코드 파일은 확장자에 맞는 코드블록으로 감쌈)
- 노트 1개는 `.md`, 여러 개는 zip으로 내려받기

**계정**
- 최초 가입자가 관리자가 되고, 이후 계정은 관리자가 발급하는 방식 (셀프호스팅 전제)
- 액세스 토큰 15분(헤더) + 리프레시 토큰 14일(HttpOnly 쿠키)

## 기술적으로 신경 쓴 부분

**노트 본문 암호화 (봉투 암호화)**
환경변수로 주입한 KEK로 사용자별 데이터 키(DEK)를 AES-GCM으로 감싸 DB에 보관하고,
노트 본문과 노트 비밀번호는 그 DEK로 암호화합니다. AAD에 사용자 식별자를 묶어 다른 사용자의 암호문을
가져와 복호화하는 것을 막고, 키 교체를 대비해 KEK 버전을 함께 저장합니다.
서버가 복호화하는 구조이므로 종단간 암호화(E2E)는 아니며, DB가 유출됐을 때 본문을 보호하는 것이 목적입니다.

**계층 분리와 자체 라이브러리**
모듈(note, tag, template, workspace, preference, search, user)마다 `domain / application / infrastructure / interfaces`
4계층으로 나눴습니다. 반복되는 골격(베이스 모델, 설정 로더, 서비스·리포지토리 기반 클래스, 관리 커맨드)은
직접 만들어 PyPI에 공개한 [fastapi-clean-archi](https://github.com/moning02004/fastapi-clean-archi)로 분리했고,
이 프로젝트가 그 라이브러리의 실사용처입니다. 새 모듈은 관리 커맨드 한 줄로 4계층 골격이 생성됩니다.

**토큰 재발급 경합 처리**
401을 받으면 리프레시를 시도하고 원래 요청을 재시도하되, 여러 요청이 동시에 401을 받아도
재발급 호출은 한 번만 나가도록 진행 중인 요청을 공유합니다. 토큰 없이 보낸 공개 노트 요청의 401은 재발급 대상에서 제외합니다.

**식별자 노출 최소화**
외부로 나가는 모든 리소스 ID는 auto increment 값이 아니라 별도 해시 ID를 사용합니다.

**작은 것들**
- API 응답 본문을 한 번만 읽어 재사용하는 에러 타입, 204·비 JSON 응답 처리
- 인덱스 설정(검색 대상 필드, 필터·정렬 가능 필드, 오타 보정 비활성)을 앱 기동 시 코드로 보장
- 매퍼 초기화 전 전 모듈 모델을 로드해, 워커가 일부 모델만 임포트할 때 생기는 관계 해석 실패 방지
- macOS 바인드 마운트에서 리로드가 동작하지 않는 문제를 폴링 감시로 우회하는 등, 개발 환경 이슈를 주석으로 남겨 기록

## 로컬 실행

Docker와 Docker Compose가 필요합니다. 저장소를 받은 뒤 `make up-build`를 실행하면
프론트엔드·백엔드·PostgreSQL·Meilisearch·Redis·Celery 워커/비트가 함께 뜹니다.
프론트엔드는 `http://localhost:3000`, API는 `http://localhost:8002`입니다.
중지는 `make down`, 로그는 `make logs`, 백엔드 테스트는 `make test`로 실행합니다.
테스트는 in-memory SQLite를 사용해 운영 DB에 접근하지 않습니다.

> 저장소에 포함된 compose 파일의 키 값들은 로컬 개발 전용입니다. 배포 시에는 반드시 교체해야 합니다.

## 아직 못 한 것 / 알려진 한계

솔직하게 적어둡니다.

- **종단간 암호화가 아닙니다.** 서버가 키를 쥐고 복호화하므로, 서버를 신뢰하는 모델입니다.
- **실시간 동시 편집을 지원하지 않습니다.** 같은 노트를 동시에 고치면 나중 저장이 이깁니다. 대신 스냅샷으로 이전 내용을 되돌릴 수 있게 했습니다.
- **검색 결과에는 페이지네이션이 아직 적용되지 않았습니다.** 일반 목록 조회는 20개 단위로 페이징합니다.
- **파일 저장소는 로컬 디스크 구현만 있습니다.** 인터페이스는 분리해 뒀지만 오브젝트 스토리지 구현은 아직입니다.
- **워크스페이스 권한은 멤버 / 비멤버 두 단계입니다.** 읽기 전용, 관리자 같은 세부 역할은 없습니다.
- **자동화 테스트는 백엔드 API 위주이고, 프론트엔드 테스트는 없습니다.**
